# 모바일 수정 후 최종 확인

기존 네 단계 수정과 이후 호환성 보완의 점검 기준입니다. 코드 반영·자동 검사 통과와 실제 휴대전화 확인은 구분합니다. 특히 S24 Ultra / 삼성 인터넷의 주소 표시줄·입력 장치 판정은 에뮬레이션만으로 완료 처리하지 않습니다.

## 가로 화면 호환성 보완

- 너비 760px 이하의 기존 배치와 태블릿 대응을 유지합니다. 가로 화면 높이가 600px 이하이면 입력 장치의 `hover`·`pointer` 판정과 관계없이 압축 배치를 적용합니다. PC 창을 낮게 줄인 경우도 포함합니다. 보관소 CSS와 탭·패널 제어 코드가 같은 조건을 사용해야 합니다.
- 메뉴 전체에 스크롤을 걸어 더보기 목록이 잘리던 충돌을 제거합니다. 더보기 목록 자체만 남은 화면 높이 안에서 스크롤하며, 읽기 설정부터 마지막 항목까지 실제로 선택할 수 있어야 합니다.
- 터치 지원 여부는 안내 문구와 키보드 힌트에 사용합니다. 펜·마우스가 주 입력 장치여도 터치를 지원하면 터치 안내를 유지합니다.
- 보고서는 상단의 중복 제목과 여백, 작은 가로 화면의 보고서 목록 높이를 줄입니다. 740×280에서 일반·큰 글자 모두 첫 문장 일부를 페이지 스크롤 없이 읽을 수 있어야 합니다. 본문 자체의 긴 내용은 계속 스크롤합니다.
- S24 Ultra / 삼성 인터넷에서 보관소 목록이 바로 보이는지, 세로↔가로 회전과 주소 표시줄 변화 후에도 기록 선택·열기가 가능한지는 배포 후 실기기 확인 대상으로 남깁니다.

## 처음부터 끝까지 읽으며 확인할 순서

### 주소 표시줄과 최소 안내 보완 (2026-10-21)

- 사용자 실기 결과: S24 Ultra / 삼성 인터넷과 iPhone 13 mini / Safari 모두 주소 표시줄을 다시 표시한 뒤 스크롤해도 숨겨지지 않는 현상이 보고되었습니다. 특정 기기만의 문제로 분류하지 않습니다.
- 보관소·장면의 `body`/앱 스크롤 잠금을 해제했습니다. 바깥 영역은 `100lvh`, 화면은 `position:sticky`와 `100dvh`를 사용합니다. 주소 표시줄이 차지하는 높이만큼 자연스러운 루트 스크롤 범위를 확보하면서, 기록 열기·메뉴는 현재 보이는 화면 안에 유지합니다. 임의의 빈 여백이나 강제 전체 화면 전환은 추가하지 않습니다.
- 목록·대사·채팅·첨부의 세로 스크롤은 경계에서 페이지로 전달됩니다. 더보기·프로필·기록 창처럼 별도 조작 중인 창은 기존 스크롤 격리를 유지합니다. 내부 본문이 스크롤 중일 때 주소 표시줄이 즉시 접히는지와 경계에 도달한 뒤 접히는지는 실기에서 따로 확인해야 합니다.
- 초기 안내는 “가로·세로 모두 즐길 수 있습니다. 컷신은 가로 화면을 권장합니다.”로 변경했습니다. 컷신이 있는 기록을 세로로 열면 **재생 전**에 가로 권장을 한 줄 표시합니다. 재생 장면 위에 회전 팝업을 띄우지 않습니다.
- 긴 보고서를 가로로 처음 열 때만 세로 권장을 한 줄 표시합니다. 화면 높이 340px 미만, 이어 읽는 위치, 목록·설정·짧은 삽입 문서에서는 표시하지 않습니다. 두 종류 안내는 각각 한 번의 페이지 방문 중 한 번만 표시하며, 회전 후 다시 권하지 않습니다. 방향 잠금은 사용하지 않습니다.
- 첫 장면의 “자동 읽기·설정은 메뉴에서” 안내를 제거했습니다. 첨부의 스크롤 안내는 “아래에 내용이 더 있습니다.”로 바꾸고, 남은 내용이 있을 때만 표시합니다.
- 자동 검사: 375×812, 812×375, 915×412에서 루트 잠금 해제, 실제 터치 입력의 스크롤 전달, 브라우저 바 높이를 모의한 반복 크기 변화, 고정된 버튼 접근, 안내 반복 방지, 회전·이어읽기 시 안내 생략을 확인합니다. 에뮬레이션의 큰/동적 뷰포트가 같으므로 별도로 크기 차이를 모의합니다. **주소 표시줄 자체의 접힘을 검증한 것은 아닙니다.**
- 실기 완료 기준: 두 기기에서 A-01 첫 진입 → 주소 표시줄 숨김 → 다시 표시 → 재차 숨김 → 목록 복귀를 반복합니다. 목록/본문 안쪽과 바깥쪽, 스크롤 처음/중간/끝에서 각각 확인하고 가로·세로 모두 기록합니다. 주소 표시줄이 보일 때와 숨겨질 때 버튼·본문이 잘리거나 큰 빈 공간이 생기지 않아야 합니다. 2026-10-22 사용자가 주소 표시줄 문제가 해결되었다고 확인했습니다.

기존 진행 기록을 보존하려면 먼저 설정의 백업 내보내기를 사용합니다. 새 진행 검사는 별도 브라우저 프로필에서 할 수 있습니다. 마지막 배포 뒤 새로고침하여 시작합니다.

1. **보관소:** 모바일 가로 화면에서 기록 목록과 선택한 기록을 여는 버튼에 긴 페이지 스크롤 없이 접근할 수 있는지 확인합니다. 디스크 전환, 기록 찾기, 읽기 설정에 들어갔다 돌아오는 것도 확인합니다.
2. **A-01:** 재생 버튼에 바로 접근할 수 있는지, 인물 식별 HUD의 위가 잘리지 않는지 확인합니다. 주소 표시줄을 보이게/숨기게 하고 가로↔세로 회전 후에도 HUD와 메뉴가 화면 안에 있어야 합니다. 종합 평가 문서는 내부 내용을 스크롤해서 끝까지 읽을 수 있어야 합니다.
3. **A-02 / A-04:** 채팅의 메시지와 인물 프로필, 첨부 문서의 확인 버튼을 확인합니다. 다음 장면으로 진행한 뒤 이전 버튼과 기록 보기를 사용해도 진행이 막히지 않아야 합니다.
4. **A-03 / A-06 / A-07:** 인물 확대·탐색·발소리 연출을 끝까지 본 뒤 다음 대사로 가서 **메뉴의 이전 버튼**을 누릅니다. 해당 장면의 연출이 다시 시작되어야 합니다. A-07은 ‘바람 소리.’ → ‘다섯 명의 발소리…’ → 이전 순서로 확인합니다. 앞뒤로 빠르게 이동해도 연출이 중복되거나 멈추지 않아야 합니다.
5. **A-08:** ‘블랙박스 및 드론’으로 표시되는지 확인합니다. 기록을 마칠 때 다음 기록 버튼이 가로 화면에서도 바로 보이는지 확인합니다. 이후 B·C·D로 넘어가는 동안 같은 기준을 적용합니다.
6. **B편:** 채팅·첨부·서술·연속 재생을 확인하고 B-07의 카메라 이동도 이전 버튼으로 다시 확인합니다. 설정에서 글자 크기를 크게 바꿔도 메뉴·본문·진행 버튼을 사용할 수 있어야 합니다.
7. **C편:** ‘잔존 랩쳐 확인 결과.’ 문장을 확인합니다. 요청에는 C-02로 적혀 있었지만 실제 저장소에서 해당 문장은 C-01에 있어 그 문장을 수정했습니다. C-02에서 메뉴 → 더보기를 열어 읽기 설정을 선택하고 돌아옵니다. 목록 안을 스크롤해 마지막 항목도 선택할 수 있어야 합니다. C-05의 ‘연화?’ 무전과 ‘두 사람에게서는 아무 응답도 돌아오지 않는다.’ 서술 사이에서 컷신의 위치와 크기가 같아야 합니다.
8. **D편:** D-01 첫 진입 시 연구자료 HUD의 틀이 뒤늦게 덧붙는 현상이 없어야 합니다. 짧은/긴 대사, 서술, 큰 글자 설정과 메뉴 열기에 따라 HUD 자체가 이동하지 않아야 합니다. D-06 검사 기록에서 ‘특별 관찰 대상’부터 ‘불필요.’까지 삭제되었는지 확인합니다. 관련 보고서를 열고 돌아와도 읽던 위치가 유지되어야 합니다.
9. **엔딩 / 설정:** 마지막 크레딧에 D편 배경 이미지의 「승리의 여신: 니케」 사용 표시가 있어야 합니다. 음악 선택은 `side story`, `I'm waiting you Commander` 두 개이며 자동 선택 항목은 없어야 합니다. 마지막 사진이 해금되면 두 번째 음악도 선택 가능해지고 보관소 기본곡으로 한 번 전환됩니다. 사진에서 곧바로 나가거나 브라우저를 다시 열어도 유지되어야 합니다. 이후 직접 고른 곡·음량·음소거도 새로고침 후 유지되어야 합니다.
10. **복원:** 연출을 본 뒤 설정에 다녀오기, 새로고침 후 이어보기, 북마크/기록으로 이동하기를 확인합니다. **이전 버튼은 연출을 다시 시작**, **설정 복귀와 이어보기는 읽던 상태를 복원**하는 것이 의도한 동작입니다. 효과 줄이기 설정에서는 과한 카메라 움직임이 없어야 합니다.

## 자동 회귀검사 범위

### 마지막 사진과 보관소 음악 보완 (2026-10-22)

- 사용자 확인: 앞선 주소 표시줄 문제는 해결되었다는 후속 결과를 받았습니다. 아래 음악 수정은 모바일과 PC 공통 로직을 대상으로 합니다.
- 원인: 사진 해금은 모든 본편 기록의 완료를 확인했지만 음악 선택은 사진의 실제 표시 완료(`endingViewed`)를 기다렸습니다. 또한 저장된 `side-story`가 항상 우선되어 사진을 보아도 보관소 기본곡이 바뀌지 않았습니다.
- 변경: 사진 해금 시 음악 해금과 기본곡 전환을 함께 저장합니다. 실제 사진 열람 기록은 별도로 유지합니다. 이미 사진이 해금되었거나 열람된 구버전 저장도 처음 불러올 때 복구하고, 이후 직접 선택한 음악은 덮어쓰지 않습니다. 진행 초기화는 음악 해금도 초기화합니다.
- 회귀 항목: 미해금 잠금 유지, 기존 저장 복구와 재접속, 마지막 기록 완료 직후 전환, 사진 표시 직후 이탈, 재생 차단, 직접 선택 유지, 다른 탭 동기화, 백업 병합에 의한 해금, 초기화 이후 오래된 탭의 상태 복원 방지. 자동 브라우저 검사는 Chromium이며 실제 기기에서의 음악 확인은 별도로 구분합니다.
