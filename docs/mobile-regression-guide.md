# 모바일 수정 후 최종 확인

이번 변경은 네 단계로 나누어 브라우저 회귀검사 후 각각 배포합니다.

| 단계 | 변경 | 주요 확인 위치 |
| --- | --- | --- |
| 1 | 문구, D편 배경 크레딧, BGM 선택 두 개 | A-08, 잔존 랩쳐 문장, D-06 검사 기록, 읽기 설정, 엔딩 크레딧 |
| 2 | 가로 화면 보관소·재생 진입·다음 기록·문서·HUD·채팅 배치 | 보관소, A-01, A-02, A-04, 기록 사이 전환 |
| 3 | 대사 형식별 컷신 위치 고정, D 연구자료 HUD 위치·첫 로딩 | C-05 무전/서술 전환, D-01 및 이후 연구자료 장면 |
| 4 | 이전 버튼으로 돌아갈 때 연출 재생 | A-03 인물 확대, A-06 탐색, A-07 발소리, B-07 카메라 이동 |

## 처음부터 끝까지 읽으며 확인할 순서

기존 진행 기록을 보존하려면 먼저 설정의 백업 내보내기를 사용합니다. 새 진행 검사는 별도 브라우저 프로필에서 할 수 있습니다. 마지막 배포 뒤 새로고침하여 시작합니다.

1. **보관소:** 모바일 가로 화면에서 기록 목록과 선택한 기록을 여는 버튼에 긴 페이지 스크롤 없이 접근할 수 있는지 확인합니다. 디스크 전환, 기록 찾기, 읽기 설정에 들어갔다 돌아오는 것도 확인합니다.
2. **A-01:** 재생 버튼에 바로 접근할 수 있는지, 인물 식별 HUD의 위가 잘리지 않는지 확인합니다. 주소 표시줄을 보이게/숨기게 하고 가로↔세로 회전 후에도 HUD와 메뉴가 화면 안에 있어야 합니다. 종합 평가 문서는 내부 내용을 스크롤해서 끝까지 읽을 수 있어야 합니다.
3. **A-02 / A-04:** 채팅의 메시지와 인물 프로필, 첨부 문서의 확인 버튼을 확인합니다. 다음 장면으로 진행한 뒤 이전 버튼과 기록 보기를 사용해도 진행이 막히지 않아야 합니다.
4. **A-03 / A-06 / A-07:** 인물 확대·탐색·발소리 연출을 끝까지 본 뒤 다음 대사로 가서 **메뉴의 이전 버튼**을 누릅니다. 해당 장면의 연출이 다시 시작되어야 합니다. A-07은 ‘바람 소리.’ → ‘다섯 명의 발소리…’ → 이전 순서로 확인합니다. 앞뒤로 빠르게 이동해도 연출이 중복되거나 멈추지 않아야 합니다.
5. **A-08:** ‘블랙박스 및 드론’으로 표시되는지 확인합니다. 기록을 마칠 때 다음 기록 버튼이 가로 화면에서도 바로 보이는지 확인합니다. 이후 B·C·D로 넘어가는 동안 같은 기준을 적용합니다.
6. **B편:** 채팅·첨부·서술·연속 재생을 확인하고 B-07의 카메라 이동도 이전 버튼으로 다시 확인합니다. 설정에서 글자 크기를 크게 바꿔도 메뉴·본문·진행 버튼을 사용할 수 있어야 합니다.
7. **C편:** ‘잔존 랩쳐 확인 결과.’ 문장을 확인합니다. 요청에는 C-02로 적혀 있었지만 실제 저장소에서 해당 문장은 C-01에 있어 그 문장을 수정했습니다. C-05의 ‘연화?’ 무전과 ‘두 사람에게서는 아무 응답도 돌아오지 않는다.’ 서술 사이에서 컷신의 위치와 크기가 같아야 합니다.
8. **D편:** D-01 첫 진입 시 연구자료 HUD의 틀이 뒤늦게 덧붙는 현상이 없어야 합니다. 짧은/긴 대사, 서술, 큰 글자 설정과 메뉴 열기에 따라 HUD 자체가 이동하지 않아야 합니다. D-06 검사 기록에서 ‘특별 관찰 대상’부터 ‘불필요.’까지 삭제되었는지 확인합니다. 관련 보고서를 열고 돌아와도 읽던 위치가 유지되어야 합니다.
9. **엔딩 / 설정:** 마지막 크레딧에 D편 배경 이미지의 「승리의 여신: 니케」 사용 표시가 있어야 합니다. 음악 선택은 `side story`, `I'm waiting you Commander` 두 개이며 자동 선택 항목은 없어야 합니다. 두 번째 음악의 기존 엔딩 해금 조건은 유지합니다. 음악 선택·음량·음소거·새로고침 후 유지도 확인합니다.
10. **복원:** 연출을 본 뒤 설정에 다녀오기, 새로고침 후 이어보기, 북마크/기록으로 이동하기를 확인합니다. **이전 버튼은 연출을 다시 시작**, **설정 복귀와 이어보기는 읽던 상태를 복원**하는 것이 의도한 동작입니다. 효과 줄이기 설정에서는 과한 카메라 움직임이 없어야 합니다.

## 자동 회귀검사 범위

- 장면 ID·북마크·진행 저장소 단위 검사 22개.
- 브라우저 검사: 요청 문구/BGM 마이그레이션, 컷신/HUD 안정성, 가로 화면, 기존 화면/입력, 문서 생명주기, 이전 연출/이어보기, 구버전 서술·북마크 복원, 음악/엔딩, 저장 가져오기, 보고서 이동.
- 가로 화면은 740×360, 915×412, 1280×540, 1536×600을 포함합니다. 세로 화면과 PC 화면도 함께 검사합니다.
- 자동 검사는 Chromium의 터치·화면 크기 에뮬레이션입니다. 실제 휴대전화의 주소 표시줄 변화와 화면 회전은 위 수동 확인에서 점검합니다.
- 검증 브랜치의 성공한 커밋을 그대로 main으로 이동한 뒤 GitHub Pages 배포 성공을 확인합니다.
